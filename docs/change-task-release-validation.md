# 变更任务引擎：发布验收清单

以下是可复用的验收步骤，不是某台服务器的运行记录，也不代表所有部署都已通过。

## 先在隔离测试机验证

使用可丢弃的 Debian 测试机或隔离环境，不在生产机上模拟断网或代理崩溃。

- 网页关闭或客户端断开后，已提交任务仍有可查询的最终状态。
- 管理代理在任务运行中退出后，任务标记为中断，不盲目重放。
- 重启后，历史任务及其成功、失败和中断状态保留。
- SSH、监听和防火墙变更拒绝原会话确认；独立连接可以确认，超时会回滚。
- 配置恢复验证正确／错误口令、独立确认、代理退出和超时回滚。
- 检查回滚后的配置确实等于事务开始前的备份。

## 发布前

1. 备份配置，保存恢复口令；确认云控制台可用。
2. 确认没有活动变更任务，保留公网和内网 SSH 两种入口。
3. 记录当前版本目录、关键服务 PID、监听端口和网络配置摘要。
4. 从刚拉取的源码执行更新，不调用仍指向旧 release 的全局更新命令。

## 发布后

- `/healthz` 返回 `{"status":"ok"}`，管理代理可以响应只读查询。
- 全局命令、模板及静态资源来自预期版本，没有链接指向临时目录。
- 登录网页可加载新静态资源；检查管理服务日志。
- 公网 SSH、AWG SSH、隧道握手及实际启用的代理／订阅服务可用。
- 对比发布前后的网络配置和监听端口；说明任何预期差异。
- 验收失败时保留现场，使用已验证的回滚方案；代码回退不是完整数据恢复。

高风险写入应在隔离环境完成断线和自动回滚验证后才启用。不要把某次测试通过当成所有版本、系统与网络环境的保证。
