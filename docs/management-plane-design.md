# server-kit 管理平面设计

## 目标

在全新 Debian 12/13 amd64 主机的仓库目录运行一次 `server-kit init`，完成最小 AWG 管理入口和管理网站初始化。管理员连接内网后，可在网页中安装、查看和管理 server-kit 的全部托管服务。

首版不是多主机中心控制器。每台受管主机独立运行管理网站，跨主机迁移使用加密备份。

## 网络拓扑

```text
管理员 AWG 节点 ───────┐
管理员 VLESS 节点 ─────┤
                       ▼
             10.20.0.1:9080
         低权限 Django 管理网站
                       │
             本机 Unix Socket
                       ▼
              受限 root 管理代理
                       │
             server-kit 管理脚本
                       ▼
 AWG / VLESS / Clash / Git / Mosh / SSH / 防火墙
```

管理网站默认使用 AWG 隧道内的 HTTP，仅绑定 AWG 服务端地址。AWG 管理员节点由源地址规则放行；VLESS 管理员节点由 UUID 对应的访问授权仅放行管理地址和端口。管理页面仍要求独立登录。

## 模块与 seam

### 管理网站模块

管理网站的接口是业务动作、表单状态、任务进度和结果。它不接触 root 文件、不拼接 Shell，也不理解脚本输出细节。

### 管理代理模块

管理代理在 Unix Socket seam 后提供一个小接口：提交已登记动作、查询任务和读取安全过滤后的结果。实现负责调用者身份校验、参数模式校验、全局变更锁、脚本适配、超时、审计、敏感信息过滤和回滚状态。

Socket 默认路径为 `/run/server-kit/manager.sock`，所有者为 `root:server-kit-web`，权限为 `0660`。代理同时使用内核进程凭据核验调用者，网络请求无法直接访问该 seam。

### 脚本适配模块

每个托管服务提供稳定的 JSON 输入输出模式。适配模块只允许调用固定脚本、固定子命令和经过模式校验的参数，禁止任意命令、环境变量和文件路径。

### 事实配置

`/etc/server-kit` 和各托管服务的既有配置仍是事实配置。SQLite 只保存管理账号和会话；root 管理动作写入独立哈希审计链。管理网站每次查询实际状态，不把服务状态复制进数据库。

稳定公网入口事实位于 `/etc/server-kit/public-endpoint.json`。其应用/确认/回滚属于回滚变更，由任务引擎固定 argv 执行；应用后进入 `waiting_rollback_confirmation`，只能从另一条独立登录连接确认。事实变更会联动申请并部署 HTTPS 证书、迁移 Clash 与普通文件的 `server_address`、重建现有订阅；证书申请、重建或服务重启失败，以及回滚超时或手动回滚时，都会恢复旧事实、旧证书、旧发布配置和旧订阅目录。只读状态独立采集本机默认路由源 IPv4 与 FQDN 的 IPv4 集合，不请求第三方“查 IP”服务。VPS 位于 NAT 后时，该地址只作诊断参考，管理员仍须以云控制台公网地址为准；DNS TTL 在标准库无法可靠取得时明确标记未知。该事实投影到新 AWG 配置、Clash AWG/VLESS 节点入口，不持有 DNS 供应商凭据，也不回收或重写客户端私钥；事实文件存在但损坏时拒绝生成新配置，不静默回退到安装期 IP。VLESS 和 SSH 公网服务监听全部本机 IPv4，server-kit 防火墙以 `meta nfproto ipv4` 限定 IPv4，并只按公网接口、受管协议与端口放行，不绑定单个易变目标 IPv4；端口范围、AWG 内网目标与默认拒绝策略保持不变。同一公网接口上的第二 IPv4 也会使用相同端口策略，因此多宿主部署必须在应用事务前复核候选规则；IPv6 业务端口不在本功能中自动开放。

## 安全不变量

- Web 进程永不以 root 运行。
- 首个超级管理员必须来自 AWG 普通节点。
- 系统始终至少保留一个启用的超级管理员和管理员节点。
- 当前访问管理网站的管理员节点不能被网页直接禁用或删除。
- 新建受限节点默认没有任何内网访问授权。
- 私钥、密码、TOTP 和完整令牌不得进入日志或审计记录。
- 查看私钥、二维码和完整订阅令牌需要重新认证并记录审计。
- 同一时间只允许一个变更任务执行。
- SSH、防火墙、AWG 入口和 VLESS 入口变更必须具有回滚窗口。
- 管理网站不提供通用 HTTP 管理令牌或任意 Shell 入口。
- 默认零遥测、零 CDN、零云端认证。

## 初始化

`server-kit init` 只完成：

1. 验证 Debian 12/13 amd64、root、systemd 和必要网络条件。
2. 安装或复用 AWG，不重置现有密钥和节点。
3. 通过 SSH 端口转发首次访问管理网站。
4. 创建超级管理员账号并启动内网管理网站。
5. 管理网站在当前浏览器生成首个管理员节点私钥和主/备双入口配置；VPS 只登记公钥与预共享密钥。节点连接后再设为管理入口。
6. 输出管理地址和恢复命令。

初始化不修改 SSH，不启用默认拒绝防火墙，也不安装其他可选托管服务。现有主机只接管已识别状态，不重装、不重启、不轮换密钥。

## 首次部署向导

推荐向导按以下依赖顺序运行：系统检查、AWG 入口验证、VLESS、机场资源与发布订阅、可选 Git/文件/Mosh、SSH 加固、防火墙确认、首份加密备份。向导可以中断后继续，完成的步骤不会重复执行。

## 资源与权限

- 内网节点：普通节点和受限节点；支持新增、禁用、启用和删除。新节点的配置和二维码只在受信任客户端本地生成。
- 机场资源：多个机场订阅、中转节点和出口节点；支持按机场与国家/地区启用、完整 Mihomo YAML、连通性测试和切换。
- 发布订阅：随新增 AWG/VLESS 节点在同一任务中自动生成；链接、二维码、停用、恢复和令牌轮换均放在对应节点卡片内。只有历史状态存在差异时才显示人工修复入口。
- 域名管理：独立标签页集中放置稳定公网入口、动态 DNS 与全局订阅强制解析，不混入节点和订阅领取操作。
- 超级管理员：管理账号、安全策略、升级和管理网站卸载。
- 管理员：管理托管服务、内网节点、机场资源和发布订阅。
- 只读用户：查看状态和审计，不查看私钥和完整令牌。

禁用只撤销授权并保留服务端公钥记录；删除会同步清理服务端授权、公钥和预共享密钥。客户端私钥与完整配置不写入 VPS。

## 任务、审计与恢复

变更任务先展示影响和差异，通过 CLI 与网页共用的全局锁串行执行。请求一旦交给 root 代理，页面关闭不会把动作变成任意命令；高风险任务进入回滚窗口，必须通过新连接确认。

审计写入 root 专属追加文件并使用哈希链检测篡改，网页读取时会校验整条链。敏感值只记录动作类型和结果。

`server-kit recovery` 仅供 SSH 或云控制台使用，负责恢复 AWG、管理网站、管理员认证和最后一次高风险变更，不承担日常管理。

## 读取与平台适配边界

- `lib/server_kit_port_facts.py` 是端口事实的唯一 module：负责一次采集、结构校验、范围分类、连续端口压缩、防火墙集合和 CLI/网页投影。Shell 脚本只提供路径与系统命令 adapter。
- `control_plane/read_model.py` 按页面意图组合主机快照、服务清单及附加资源，声明响应版本和短期新鲜度；网页不再决定需要执行几次主机采集。
- `web/dashboard/ssh_scripts.py` 定义 SSH 综合管理器的共同动作契约，Windows、Linux、macOS 和 Termux 文件只实现操作系统差异。
- `web/dashboard/deployment_guide.py` 固定“安装软件 → 创建节点 → 发布订阅 → 配置隧道 → 验证”的接入旅程，桌面平台额外接入同一 SSH 管理步骤。

这些边界均保留旧代理的滚动升级 adapter；新代码只调用上述深层接口，不再新增并行解析路径。

## 更新、备份与卸载

管理网站更新安装到独立版本目录，HTTP 与 Unix Socket 健康检查成功后原子切换，失败自动回退。代码仓库更新和发布权限由外部 Gitea 管理；网页不提供任意仓库地址或任意升级命令。

管理平面代码位于 `/opt/server-kit/releases/<版本>`，`/opt/server-kit/current` 只作为原子切换入口。低权限 Web 用户不直接读取通常位于 `/root` 下的 Git 工作树。

配置备份包含服务状态、密钥和管理网站数据，并使用用户恢复口令加密。Git 仓库等大体量数据独立备份。恢复前生成当前状态回滚包并展示覆盖范围。

卸载分为管理网站卸载、单项托管服务卸载和整套彻底清理。彻底清理只能从 SSH 或控制台执行，并要求先备份及输入服务器指纹。

## 分阶段验收

1. 初始化、认证、只读总览、审计、现有服务接管和 AWG 节点管理。
2. VLESS 访问矩阵、Clash、Git、文件服务和 Mosh。
3. SSH/防火墙事务、备份恢复、任务审计与账号角色。
4. 在一次性 Debian 12/13 虚拟机验证全新安装、断网、崩溃和自动回滚，再以接管模式部署当前 VPS。

入口类高风险写操作必须先在一次性测试机完成断线、崩溃和自动回滚验证；普通节点、订阅和机场资源使用原子替换与失败回退。
