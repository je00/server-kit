# VPS 公网 IPv4 变更 runbook

稳定入口只能降低恢复时间，不能承诺零中断。客户端、操作系统和递归 DNS 都可能在 TTL 到期后继续缓存旧地址；UDP 会话也不会在地址变化后无缝迁移。

## 事前准备

1. 为受管主机准备专用 FQDN（例如 `vpn.example.com`）及一个 A 记录，并在管理网站配置 DNSPod 或 DuckDNS 自动更新。凭据只保存在 VPS 的 root-only 配置中；配置时会先真实上报当前默认路由公网 IPv4，成功后才启用定时器。定时器启用或系统开机后约 1 秒开始上报，失败时每 5 秒重试，成功后每分钟继续对账。
2. 至少在计划变更前一个旧 TTL 周期，把 A 记录 TTL 降到供应商允许的合理低值（常见为 60–300 秒），并等待旧 TTL 完整过去。
3. 在“域名管理 → 稳定公网入口”输入 FQDN，检查 root 事实预览并应用任务。事实写入 `/etc/server-kit/public-endpoint.json`，原子替换、权限 `0600`。应用后进入 5 分钟回滚窗口，必须从另一条独立登录连接点击“确认保留”；否则超时自动恢复入口事实。任务会联动申请 HTTPS 证书、迁移 Clash/普通文件发布地址并重建现有订阅；失败、手动回滚或超时时会同时恢复旧事实、旧证书、旧发布配置和旧订阅。该文件会被后续创建的加密备份包含，但端点任务本身不会自动创建新备份。
4. 等待页面显示 FQDN 的 IPv4 集合包含本机默认路由源 IPv4。该诊断不会请求第三方“查 IP”服务；如果 VPS 位于 NAT 后，本机路由地址可能不是云控制台分配的公网地址，此时页面会明确提示并应以云控制台地址为准。TTL 显示“未知”是刻意行为：Python 标准库解析接口不能可靠返回 TTL。
5. 既有节点在管理网站的“安全事务”页面（`/security/transactions/`）对“VLESS 公网监听迁移”执行预览和应用，再从另一条独立连接确认保留。该事务只把 `vless-public` 入站改为监听全部本机 IPv4，先校验 Xray 候选配置，失败或超时会自动回滚；UUID、REALITY 密钥、short-id、端口和 SNI 不变。新安装默认已经使用该模式。
6. 通过管理网站既有的 SSH 监听高风险事务重新预览、应用并从独立连接确认一次；最终公网高位端口监听 `0.0.0.0`，AWG 的 `10.20.0.1:22` 保持不变，公网 22 不会开放。然后用既有防火墙高风险事务重新生成、应用并确认规则；公网规则由 `meta nfproto ipv4` 限定为 IPv4，只匹配公网接口、受管协议和端口，但不再绑定易变目标 IPv4。同一接口存在多个 IPv4 时这些地址共享端口策略，须在候选规则中人工复核；本功能不会开放 IPv6 业务端口。开机恢复会重新探测默认 IPv4 路由接口；接口名变化时只替换已确认规则中的四条公网接口绑定，保留端口集合与其余策略，校验失败则不覆盖持久规则并由 systemd 稍后重试。不要跳过首次应用时的自动回滚与第二连接验证。
7. 新创建的 AWG 两份配置会使用该 FQDN，并保留主入口与一个备用 UDP 端口。Clash 中生成的 AWG 入口、VLESS 公网入口以及普通文件/Clash 发布 URL 都使用同一稳定入口事实。证书定时任务继续对账地址和证书；令牌与端口不会因入口迁移而轮换。

## 迁移旧 AWG 节点

VPS 从未保存客户端私钥，因此不能也不应替管理员重写旧配置。在可信客户端上，对 `*-main.conf`、`*-backup1.conf` 各做一次本地修改；历史 `*-backup2.conf` 若仍保留，也按同样方式迁移：

```diff
-Endpoint = 203.0.113.10:8443
+Endpoint = vpn.example.com:8443
```

只替换等号右侧最后一个冒号前的主机；每份文件保留原端口，并逐项确认 `PrivateKey`、`PresharedKey`、`Address`、`PublicKey`、`AllowedIPs` 和其余字段未变。先备份原文件，写回时保持 `0600`，逐个入口连接验证后再删除备份。离线浏览器扩展提供“迁移旧 AWG 配置入口”区，逐份调用 `migrateEndpointHost(config, fqdn)`；它要求配置恰好有一个 Endpoint，只返回替换后的文本，不发网络请求、不写浏览器存储。不要把旧配置粘贴到 VPS、工单或聊天工具。

## 计划内 IP 变化

1. 在云供应商控制台取得新 IPv4，不要清除 server-kit 中的稳定入口或动态 DNS 配置。开机后自动更新会尽快上报新地址；如果没有启用动态 DNS，则人工更新 FQDN 的 A 记录。
2. 等待至少一个当前 TTL，并从两个以上外部递归解析器/不同网络检查 A 记录一致。
3. 打开“域名管理”页只读诊断，确认“本机路由 IPv4”已更新且“包含路由 IP”为“是”。若页面提示 NAT，则改为人工核对云控制台公网 IPv4 是否包含在 DNS A 记录中。诊断网络失败只会显示错误，不会改写事实或阻断页面。完成上述一次性监听/防火墙迁移后，不需要因 IP 变化重写 Xray、SSH 或 server-kit 防火墙配置。
4. 从 VPS 外部依次验证 AWG 的两个 UDP 入口、SSH 公网路径、AWG 内网 SSH 和 `10.20.0.1:9080` 管理路径。UDP 不能靠 TCP 端口扫描证明可用，应使用真实 AWG 握手/流量。
5. 恢复正常 TTL 前，再等待解析一致并观察客户端重连。保留旧 IP 的控制权时，可在迁移窗口内维持旧入口以吸收缓存。

## 灾后恢复

1. 从云控制台取得新 IPv4并检查 A 记录。已启用动态 DNS时，server-kit 会在网络可用后自动上报并重试；若定时器或 DNS 服务商异常，则从云控制台人工更新记录。
2. 等待可用解析器刷新后，从外部尝试两个 AWG UDP 入口、SSH 和管理路径。
3. 登录节点页运行只读诊断，或在控制台运行：

   ```bash
   server-kit-manager.sh network public-endpoint status --json
   debian_file_manager.sh audit-public-ip
   ```

4. 若 HTTPS 发布地址或证书仍属于旧 IP，可等待开机后两分钟的自动检查，或立即运行 `debian_file_manager.sh reconcile-public-ip --yes`。该操作保留现有令牌与端口；申请新证书、重建订阅或重启服务失败时会恢复原配置和发布目录。
5. 若节点尚未完成一次性迁移且新 IP 已经生效，恢复 AWG 和管理网站后，在 `/security/transactions/` 使用 VLESS 公网监听事务完成迁移；SSH 或防火墙仍绑定旧 IP 时，使用对应高风险事务重新应用。无法进入网站时，`server-kit recovery` 只能恢复 AWG/管理网站，或回滚仍处于待确认状态的稳定公网入口、VLESS 监听、SSH、防火墙、配置恢复事务；不得把它当作任意历史配置/备份选择器，也不得绕过事务直接覆盖规则。
6. 若 `/etc/server-kit/public-endpoint.json` 损坏，优先通过恢复后的管理网站重新设置稳定入口；新 AWG/VLESS/Clash 配置在事实损坏时会拒绝生成，不会静默回退到旧 IP。若其他服务配置损坏，应在管理网站的“加密备份”流程中选择最近备份、预览并应用恢复；恢复口令不保存在服务器，覆盖恢复仍遵循既有回滚窗口。只有已经开始且待确认的恢复事务，才可由 `server-kit recovery` 回滚。
7. 若 DNS 已正确但客户端仍命中旧 IP，按客户端 DNS 缓存策略重启隧道/网络服务；不要轮换节点密钥作为 DNS 故障的“修复”。
